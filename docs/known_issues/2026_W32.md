## The ingestion config defaults to SPIJ for every module

> **Deferred on purpose** · this is **D-3**
> **Detected:** 2026-08-04 · **Last verified:** 2026-09-08 against `main` — still there, `src/modules/spij/config/index.ts:72-76`

```ts
ingestSource: env.get(ENV.INGEST_SOURCE).default(sourceByKey("spij").canonicalName).asString(),
ingestStatus: env.get(ENV.INGEST_STATUS).default("Vigente").asString(),
```

The config lives under `src/modules/spij/` and its default source is SPIJ, but it
is the config every module inherits when ingesting through the assistant. Anyone
running another source without setting `INGEST_SOURCE` labels its documents as
SPIJ — and `source` is the field the platform filters by, with an **exact** match.

It was deferred deliberately: in practice the variable is always set. It stays
recorded because it is silent — nothing fails, the documents simply land under the
wrong source, and it is only visible from the platform's filters.

## `www.gob.pe`'s real budget has never been measured

> **Live, and it blocks the critical path** · this is **T-2**
> **Detected:** 2026-08-07 · **Last verified:** 2026-08-07 against `abcc2fb`
> Full evidence: `git show 3792b14:docs/registro/2026-08-07/ejecucion-fases-modulos-completos.md` § 5.1

**14 of 22 modules share `www.gob.pe`** and the throttle is per process, so naive
parallelism multiplies the rate against a single portal by 14. Nobody has measured
how many requests that portal tolerates before answering 429/403.

Until it is measured, the size of the gob.pe lane is a guess. The ceiling is the
host, not the RAM — around 8-10 modules per host was the working estimate, and an
estimate is what it still is.

Measuring it is work, and it is in `../BACKLOG.md`. What is recorded here is that
**a number in the launch plan is unverified**, so do not quote it as if it were.

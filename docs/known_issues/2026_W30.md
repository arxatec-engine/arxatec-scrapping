## Document identity relies on a local ledger the backend does not enforce

> **Live by design** · this is **A1**, decided rather than fixed
> **Detected:** 2026-07-21 · **Last verified:** 2026-08-22 against `main`
> Full evidence: `git show 3792b14:docs/registro/2026-07-21/deuda-tecnica.md` § A1

The assistant does not deduplicate: send the same document twice and it is stored
twice — two rows, two copies in S3, two entries in the vector store. The only thing
stopping that today is the scraper's local ledger.

The owner decided on 2026-07-21 that **the ledger is the official mechanism** and
backend dedup is future, medium-low priority. So this is not a bug waiting to be
fixed; it is a trap you must know about, because the ledger has two blind spots:

- If the ledger is wiped (a fresh machine, a cleared volume), re-ingesting
  duplicates everything it re-ingests.
- If the same document arrives **from two different sources**, the ledger does not
  see it: two source URLs, two identities.

The second blind spot has already been observed in the wild — see
[`2026_W34.md`](2026_W34.md).

## `status` is written in two languages and nobody validates it

> **Live** · this is **A2** · critical but deferred; the provisional answer is "everything `Vigente`"
> **Detected:** 2026-07-21 · **Last verified:** 2026-09-08 against `main` — `src/modules/spij/config/index.ts:76` still defaults to `"Vigente"`

The scraper sends `"Vigente"`; the assistant uses `"active"` internally. Nothing
validates the crossing, so the database ends up holding two vocabularies and
filtering by status becomes unreliable.

The owner's provisional decision (2026-07-21) is to send **everything as
`"Vigente"`**, which is also the only value the production filters find. That
keeps the product working and leaves the mismatch in place.

Why it stays here rather than in the backlog: the platform filters documents by
`status` with an **exact** match, so the day a source starts emitting a real
status, whatever it emits has to already agree with three repos. Read
`../fuentes-canonicas.md` and the workspace `CLAUDE.md` before touching it.
